# GEN-2 v3: retained candidates and selection within splits

v1, v2 and the completed `items/verb1/gen2_v2_requests/` remain immutable.
V3 does not recover discarded v2 proofs: v2 retained only its five selected executions.
The first v3 run must regenerate candidates. Later selection-only changes can reuse v3 pools.

## Run and resume

```bash
bash scripts/build_gen2_v3.sh
bash scripts/build_gen2_v3.sh --resume
```

Defaults: same CKG-1/2/3 inputs, `configs/tasks/gen2_v3.json`, new output `items/gen2/v3/`.
`--chapter`, `--max-candidates-per-chapter`, `--out` and `BENCH_ROOT` work as before.
No full v3 production run is started by implementing this code.

Each `candidate_pools/<chapter>.json` preserves **every gate-passing candidate**, its
question/answer, independently checked proof, input pins, approved alias records and resolved
target, including candidates later held out. Pool G11 stays pending; these are private candidates,
not automatically approved benchmark questions. Final `chapters/<chapter>.json` contains selected
items and explicit gate/selection rejections, with a pointer to the pool. Request preparation
reads only final selected items. Do not send candidate pools to Qwen as approved questions.

Generation checkpoints use a separate pool fingerprint. Selection is deterministic and rerun
from completed pools after interruption. All pools and final outputs are hashed. A completed
`--resume` also independently rechecks every retained candidate proof and source binding.
New quality/collection limits can be tried without regenerating candidates:

```bash
bash scripts/build_gen2_v3.sh --pool-source /data/151-3/comics/ComicsQA_Benchmark/items/gen2/v3 \
  --config /path/to/revised-selection.json \
  --out /data/151-3/comics/ComicsQA_Benchmark/items/gen2/v3_reselected
```

Only `quality` and `collection` settings can differ for this reuse. Base generation settings,
code, input snapshots and review-file contents must match. Changing seed, base policy or alias
approvals requires a new generation run; newly eligible candidates are absent from old pools.
Choose a fresh output for changed settings. Nothing overwrites an earlier selection or pool.

## Selection contract

The new 70% count-type, 35% count-value and 50% page-offset limits apply **within each dataset
split**, across chapters. Different splits never subsidize each other's distributions. Existing
30% frequent-name and 5% two-option caps remain per chapter, with their original denominators
and frequent-character definition. No numeric caps were silently relaxed.

`collection.max_name_answer_share` defaults to 0.50 among selected name answers, checked for
both identity and normalized displayed form. This catches repeated answers such as ZOMBIE DEVIL
and repeated role strings shared by different identities. It supplements, not replaces, the
old frequent-character-on-pages quota.

Resolved-target deduplication stays in place. Chapter round-robin ranking precedes capacities;
when trimming a violation, prefer dropping from better-represented chapters. Before/after split
reports show contributing chapters, missing chapters, families, count values, name identities/forms
and page offsets. Coverage is a preference, not a quota override. This remains conservative
trimming without refill, not a maximum-yield optimizer or proof of mathematical infeasibility.
If constraints cannot be satisfied by the retained subset, it can be empty; the full proof-passing
pool is still saved. Balanced selection cannot manufacture name diversity or hard questions.

## Reviewed aliases

Generate a **pending** review file (no automatic approvals):

```bash
bash scripts/review_gen2_aliases.sh --out /tmp/gen2-alias-reviews.json
# A bounded review file is also supported:
bash scripts/review_gen2_aliases.sh --chapter blue-exorcist__c002 --out /tmp/blue-exorcist-aliases.json
```

Each row includes chapter/identity/canonical name, exact alias, graph and visibility SHA256 pins,
visibility evidence IDs, OCR strings and relative image paths. Inspect the original images and
identity context. A readable ordinary word is not sufficient proof that it is a character name.
Do not approve fragments such as The or DEBT merely because they occur on the page.
For a genuinely reviewed valid alias, set:

```json
{"decision":"approved","name_use":"character_name","reviewer":"actual reviewer","note":"specific justification"}
```

Edit those fields on the generated row; retain its actual snapshot pins and evidence IDs.
Leave uncertain rows pending or mark rejected. Approved rows require a registered, non-generic
identity/form, exact-form verified readability, matching source snapshots, valid evidence IDs,
and a nonempty reviewer/justification. Duplicate/stale/invalid approvals fail closed. A review
cannot create an alias, manufacture OCR visibility, alter a proof or resolve an ambiguous name
anchor. Review records are provenance declarations, not cryptographically authenticated signatures.

```bash
bash scripts/build_gen2_v3.sh --alias-reviews /path/to/reviewed-aliases.json
```

No real alias approvals ship with this implementation. Without a file, canonical-only eligibility
remains. Full canonical role labels still need human review. Existing interpreter display selection
is unchanged: if it renders an unapproved alias, the name-answer candidate is held out, even if a
different alias was approved. A future explicit display-form policy would need its own contract.

## Request preparation and current limitations

The completed v2 pack contains exactly five requests, as expected from five selected source items.
Zero-request chapter messages are not errors. `prepared_not_inferred` means no Qwen inference;
G10 and human review remain pending. The terminal paste corruption does not change the saved files.

After completing and reviewing v3, use a new request destination explicitly:

```bash
bash scripts/prepare_verb1_gen2.sh \
  --source /data/151-3/comics/ComicsQA_Benchmark/items/gen2/v3 \
  --out /data/151-3/comics/ComicsQA_Benchmark/items/verb1/gen2_v3_requests
```

The adapter supports this final-chapter schema; generation changes do not require rewriting old
request packs. Existing name quotas may still exclude most name answers; reviewed aliases and
additional supported families/evidence are needed when selection reports a shortfall. No yield
increase is promised by moving selection scope alone. Qwen remains deferred to MN5.
